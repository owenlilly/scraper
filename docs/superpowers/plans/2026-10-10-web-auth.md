# Web Auth Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add the Next.js web app's server side: invitation-only accounts with email confirmation and sign-in, password reset, an administrator's invitation routes, short-lived tokens for the Python API, and account deletion that erases the Python API's data first.

**Architecture:** A new `web/` project (Next.js App Router, TypeScript) holds Better Auth, configured in one file, on the same Postgres as the Python API but in its own `auth` schema. Invitations are rows in that schema (hashed single-use tokens). The browser asks Better Auth for a 15 minute EdDSA token and sends it to the Python API, which verifies it against the keys published here. The routes are thin wrappers over functions that are tested directly against a real Postgres.

**Tech Stack:** Next.js 16, React 19, better-auth 1.7 (email and password, `admin` and `jwt` plugins), pg, Resend (plain `fetch`), Vitest, tsx.

**Spec:** `docs/superpowers/specs/2026-10-09-nextjs-auth-hosted-design.md`. This is the second of three plans: (1) the Python backend (done), (2) this plan, (3) the web app's screens and removal of NiceGUI. The screens are deliberately absent here: `web/src/app/page.tsx` is a placeholder, and plan 3 designs every page with the frontend-design skill.

**Where this plan departs from the spec:** the spec's Better Auth `hooks.before` description is implemented exactly (a header carries the token); it adds a `rateLimit` table (database-backed limits), a same-origin check on the administrator routes, an end-to-end script that runs both real servers, and a documented limitation that a token outlives a deleted or banned account by up to 15 minutes. It uses the previous major versions of TypeScript (5.9) and Vitest (4.1) rather than the brand-new ones (7.0, 5.0).

## Global Constraints

- Node 20.9 or newer (this plan was built on Node 24 and npm 11). Every dependency is pinned to an exact version: Next 16.4.0, React and React DOM 19.3.0, better-auth 1.7.6, pg 8.23.1, TypeScript 5.9.3, Vitest 4.1.11, tsx 4.23.15.
- Better Auth's tables, and the invitation table, live in the Postgres `auth` schema only, reached through a pool whose `search_path` is `auth`. Nothing of this app is created in `public` or in the Python API's `app` schema.
- Invitation-only: an account can be created only with the single-use token emailed to that exact address, sent in the `x-invite-token` header of `POST /api/auth/sign-up/email`. The token is stored only as a SHA-256 hash. The one exception is `ADMIN_EMAIL`, which may sign up without a token while no administrator exists, and becomes the administrator.
- Sign-in requires a confirmed email address. Passwords are at least 12 characters. Resetting a password ends every other session.
- The token for the Python API: 15 minutes, EdDSA (Ed25519), claims `sub`, `iss`, `aud`, `iat` and `exp` only (never an email or a name). `iss` is `BETTER_AUTH_URL`; `aud` is `API_AUDIENCE`. The keys are published at `/api/auth/jwks`.
- Deleting an account (by the person or an administrator) first asks the Python API to erase that person's data (`DELETE /account-data`, authenticated by `X-Service-Secret`). If that fails the account stays and the error says whether to retry.
- Production means `NODE_ENV=production`: https only, Secure cookies, rate limits kept in the database, and the `log` email transport refused.
- Administrator routes need a signed-in, non-banned user whose role is `admin`, and every change must carry an `Origin` header equal to this app's address or a trusted origin.
- Settings are checked at start-up with error messages that name the variable and never print its value.
- The database tests need `WEB_TEST_DATABASE_URL`, pointing at a scratch database whose name contains "test" (its `auth` schema is dropped and recreated). Unset or wrongly named is an error, never a skip.
- No screens in this plan: `src/app/page.tsx` is a placeholder. All UI is designed and built in the next plan, with the frontend-design skill.
- Never write an em dash in code comments, documents or messages. Commit messages are short imperative sentences with no attribution lines. Work on branch `nextjs_auth_hosted`; never commit to `main`.

## Review Focus

These are failure modes the spec implies that no single task's tests would otherwise hold in view, most likely first.

1. **Account creation around the invitation check.** Another spelling of the sign-up URL, another endpoint that can create a user or set a role, two sign-ups racing on one invitation, or a role sent along with a sign-up. Expected: none of them produces an account or an administrator without a valid invitation, and a race produces exactly one account with no server error. Pinned by the "ways around the invitation check" tests in `tests/signup.test.ts` (Task 4). They must keep passing after every Better Auth upgrade, because the check is a hook on one path.
2. **Deleting an account while the Python API cannot erase the data.** The API being down, slow, refusing, or busy stopping a run. Expected: the account is not deleted, the person is told to retry, and nothing is half done. Pinned by `tests/deletion.test.ts` (Task 6) and the last step of `npm run e2e` (Task 10).
3. **The two services disagreeing about the token.** A trailing slash or different scheme in `BETTER_AUTH_URL` versus `SCRAPER_JWT_ISSUER`, a different audience, or a different service secret. Expected: it fails at once and loudly, not on first real use. Pinned only by `npm run e2e`, which runs both real servers; `docs/hosted-deploy.md` has the table of settings that must agree. Run the e2e after any change to either side's settings.
4. **A token that outlives the account.** A banned or deleted person's token still passes the API's check for up to 15 minutes. Expected: harmless, because a ban ends their sessions (no new token) and deletion erases the API's data first. Documented as a known limitation in `docs/hosted-deploy.md`; not tested, because it is a property of short-lived tokens.
5. **Email going wrong.** Resend refusing or being unreachable while sending an invitation. Expected: the invitation is not left open (revoked) and the administrator is told. Pinned by "leave no open invitation behind when the email cannot be sent" in `tests/admin.test.ts` (Task 8). Verification and reset emails that fail are reported as errors by Better Auth; they are not retried by this plan.

```
/** The web app's settings, read from the environment once and checked up front so a mistake fails at start-up, by name. */

export type WebEnv = {
  databaseUrl: string;
  authSecret: string;
  baseUrl: string;
  apiUrl: string;
  apiAudience: string;
  serviceSecret: string;
  emailTransport: "resend" | "log";
  resendApiKey: string;
  emailFrom: string;
  adminEmail: string | null;
  trustedOrigins: string[];
  inviteTtlDays: number;
  production: boolean;
};

type Source = Record<string, string | undefined>;

function isHttpUrl(value: string): boolean {
  try {
    const url = new URL(value);
    return url.protocol === "http:" || url.protocol === "https:";
  } catch {
    return false;
  }
}

const trimSlash = (value: string) => value.replace(/\/+$/, "");

export function loadEnv(source: Source = process.env): WebEnv {
  const problems: string[] = [];
  const get = (name: string) => (source[name] ?? "").trim();
  const production = source.NODE_ENV === "production";

  const databaseUrl = get("DATABASE_URL");
  if (!databaseUrl) problems.push("DATABASE_URL is required");

  const authSecret = get("BETTER_AUTH_SECRET");
  if (authSecret.length < 32) problems.push("BETTER_AUTH_SECRET must be at least 32 characters (try: openssl rand -base64 32)");

  const baseUrl = trimSlash(get("BETTER_AUTH_URL"));
  if (!isHttpUrl(baseUrl)) problems.push("BETTER_AUTH_URL must be this app's public address, such as https://app.example.com");
  else if (production && !baseUrl.startsWith("https://")) problems.push("BETTER_AUTH_URL must use https in production");

  const apiUrl = trimSlash(get("API_URL"));
  if (!isHttpUrl(apiUrl)) problems.push("API_URL must be the Python API's address, such as https://api.example.com");

  const apiAudience = trimSlash(get("API_AUDIENCE") || apiUrl);

  const serviceSecret = get("SERVICE_SECRET");
  if (serviceSecret.length < 24) problems.push("SERVICE_SECRET must be at least 24 characters and equal the API's SCRAPER_SERVICE_SECRET");

  const resendApiKey = get("RESEND_API_KEY");
  const requested = get("EMAIL_TRANSPORT");
  const emailTransport = (requested || (resendApiKey ? "resend" : "log")) as WebEnv["emailTransport"];
  if (emailTransport !== "resend" && emailTransport !== "log") problems.push("EMAIL_TRANSPORT must be resend or log");
  if (emailTransport === "log" && production) problems.push("EMAIL_TRANSPORT=log would print invitation links to the server log; use resend in production");
  const emailFrom = get("EMAIL_FROM");
  if (emailTransport === "resend" && !resendApiKey) problems.push("RESEND_API_KEY is required when EMAIL_TRANSPORT is resend");
  if (emailTransport === "resend" && !emailFrom) problems.push("EMAIL_FROM is required when EMAIL_TRANSPORT is resend, such as Page Chat <no-reply@example.com>");

  const adminRaw = get("ADMIN_EMAIL").toLowerCase();
  if (adminRaw && !/^[^@\s]+@[^@\s]+\.[^@\s]+$/.test(adminRaw)) problems.push("ADMIN_EMAIL must be an email address");

  const trustedOrigins = get("TRUSTED_ORIGINS")
    .split(",")
    .map((origin) => origin.trim())
    .filter(Boolean);
  for (const origin of trustedOrigins) if (!isHttpUrl(origin.replace("*", "x"))) problems.push("TRUSTED_ORIGINS holds an entry that is not an address");

  const ttl = Number(get("INVITE_TTL_DAYS") || "7");
  if (!Number.isInteger(ttl) || ttl < 1 || ttl > 30) problems.push("INVITE_TTL_DAYS must be a whole number from 1 to 30");

  if (problems.length) throw new Error(`Invalid environment:\n- ${problems.join("\n- ")}`); // names only: values may be secrets

  return {
    databaseUrl, authSecret, baseUrl, apiUrl, apiAudience, serviceSecret, emailTransport, resendApiKey, emailFrom,
    adminEmail: adminRaw || null, trustedOrigins, inviteTtlDays: ttl, production,
  };
}
```

- [ ] **Step 3: Create `web/src/lib/email.ts`**

Email is one function type, so Resend can be swapped by writing another sender. Resend's error body is never copied into an error (it can repeat the message and the address). Every value placed in the html is escaped.

```
/** Sending email. One function type, so Resend can be swapped for anything else by writing another sender. */

export type EmailMessage = { to: string; subject: string; text: string; html: string };
export type EmailSender = (message: EmailMessage) => Promise<void>;

export class EmailError extends Error {
  constructor(public readonly status: number) {
    super(`The email service answered ${status}`); // never the response body: it can repeat the message
  }
}

const RESEND_URL = "https://api.resend.com/emails";

export function resendSender(options: { apiKey: string; from: string; fetchImpl?: typeof fetch; timeoutMs?: number }): EmailSender {
  const { apiKey, from, fetchImpl = fetch, timeoutMs = 10_000 } = options;
  return async (message) => {
    let response: Response;
    try {
      response = await fetchImpl(RESEND_URL, {
        method: "POST",
        headers: { authorization: `Bearer ${apiKey}`, "content-type": "application/json" },
        body: JSON.stringify({ from, to: [message.to], subject: message.subject, text: message.text, html: message.html }),
        signal: AbortSignal.timeout(timeoutMs),
      });
    } catch {
```

```
/** The scratch database the tests may wipe. They drop and recreate its `auth` schema, so the name must say "test". */
export function testDatabaseUrl(): string {
  const url = process.env.WEB_TEST_DATABASE_URL;
  if (!url) throw new Error("Set WEB_TEST_DATABASE_URL to a scratch Postgres database. These tests drop and recreate its `auth` schema.");
  const name = /^postgres(?:ql)?:\/\/[^/]*\/([^?#]*)/.exec(url)?.[1] ?? ""; // not `new URL`: it rejects socket-style addresses with no host
  if (!/test/i.test(name)) throw new Error(`Refusing to use database "${name}": the name must contain "test", because the tests wipe it.`);
  return url;
}

export async function freshSchema(): Promise<Pool> {
  const admin = new Pool({ connectionString: testDatabaseUrl() });
  await admin.query("DROP SCHEMA IF EXISTS auth CASCADE");
  await admin.query("CREATE SCHEMA auth");
  await admin.end();
  return makePool(testDatabaseUrl());
}

export async function inviteOnlyPool(): Promise<Pool> {
  const pool = await freshSchema();
  await pool.query(INVITE_TABLE_SQL);
  return pool;
}
```

- [ ] **Step 5: Create `web/src/lib/invites.ts`**

The token in the email is random (32 bytes) and only its SHA-256 hash is stored, so a copy of the table cannot be used to sign up. A new invitation replaces any earlier one still waiting for the same address. The reason a check failed is for tests and logs; the person is never told which.

```
import { createHash, randomBytes } from "node:crypto";
import type { Pool } from "pg";

export const INVITE_TABLE_SQL = `
CREATE TABLE IF NOT EXISTS auth.invite (
  id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  email text NOT NULL,
  token_hash text NOT NULL UNIQUE,
  invited_by text,
  created_at timestamptz NOT NULL DEFAULT now(),
  expires_at timestamptz NOT NULL,
  used_at timestamptz,
  revoked_at timestamptz
);
CREATE INDEX IF NOT EXISTS invite_email ON auth.invite (email);
`;

export type InviteStatus = "pending" | "used" | "revoked" | "expired";
export type Invite = {
  id: string;
  email: string;
  invitedBy: string | null;
  createdAt: Date;
  expiresAt: Date;
  usedAt: Date | null;
  revokedAt: Date | null;
  status: InviteStatus;
};
export type InviteCheck = { ok: true; id: string } | { ok: false; reason: "missing" | "unknown" | "wrong_email" | "used" | "revoked" | "expired" };

export const normalizeEmail = (email: string) => email.trim().toLowerCase();
const hashToken = (token: string) => createHash("sha256").update(token).digest("hex");

const COLUMNS = `id, email, invited_by, created_at, expires_at, used_at, revoked_at,
  CASE WHEN used_at IS NOT NULL THEN 'used' WHEN revoked_at IS NOT NULL THEN 'revoked' WHEN expires_at <= now() THEN 'expired' ELSE 'pending' END AS status`;

type Row = {
  id: string;
  email: string;
  invited_by: string | null;
  created_at: Date;
  expires_at: Date;
  used_at: Date | null;
  revoked_at: Date | null;
  status: InviteStatus;
};

const toInvite = (row: Row): Invite => ({
  id: row.id,
  email: row.email,
  invitedBy: row.invited_by,
  createdAt: row.created_at,
  expiresAt: row.expires_at,
  usedAt: row.used_at,
  revokedAt: row.revoked_at,
  status: row.status,
});

/** Invitations. The token that goes in the email is never stored, only its hash, so a copy of the table cannot be used to sign up. */
export class InviteStore {
  constructor(
    private readonly pool: Pool,
    private readonly ttlDays: number,
  ) {}

  /** A new invitation replaces any earlier one still waiting for the same address. */
  async create(email: string, invitedBy: string | null): Promise<{ invite: Invite; token: string }> {
    const address = normalizeEmail(email);
    const token = randomBytes(32).toString("base64url");
    const client = await this.pool.connect();
    try {
      await client.query("BEGIN");
      await client.query("UPDATE auth.invite SET revoked_at = now() WHERE email = $1 AND used_at IS NULL AND revoked_at IS NULL", [address]);
      const { rows } = await client.query<Row>(
        `INSERT INTO auth.invite (email, token_hash, invited_by, expires_at) VALUES ($1, $2, $3, now() + make_interval(days => $4))
         RETURNING ${COLUMNS}`,
        [address, hashToken(token), invitedBy, this.ttlDays],
      );
      await client.query("COMMIT");
      return { invite: toInvite(rows[0]), token };
    } catch (error) {
      await client.query("ROLLBACK");
      throw error;
    } finally {
      client.release();
    }
  }

  /** Is `token` a live invitation for exactly this address? The reason is for tests and logs, never for the person. */
  async check(token: string, email: string): Promise<InviteCheck> {
    if (!token) return { ok: false, reason: "missing" };
    const { rows } = await this.pool.query<Row>(`SELECT ${COLUMNS} FROM auth.invite WHERE token_hash = $1`, [hashToken(token)]);
    const row = rows[0];
    if (!row) return { ok: false, reason: "unknown" };
    if (row.email !== normalizeEmail(email)) return { ok: false, reason: "wrong_email" };
    if (row.status === "used") return { ok: false, reason: "used" };
    if (row.status === "revoked") return { ok: false, reason: "revoked" };
    if (row.status === "expired") return { ok: false, reason: "expired" };
    return { ok: true, id: row.id };
  }

  /** The address now has an account, so any invitation still waiting for it is spent. */
  async consume(email: string): Promise<void> {
    await this.pool.query("UPDATE auth.invite SET used_at = now() WHERE email = $1 AND used_at IS NULL AND revoked_at IS NULL", [normalizeEmail(email)]);
  }

  /** True when a pending invitation was revoked; false when there was nothing to revoke. */
  async revoke(id: string): Promise<boolean> {
    if (!/^[0-9a-f-]{36}$/i.test(id)) return false;
    const result = await this.pool.query("UPDATE auth.invite SET revoked_at = now() WHERE id = $1 AND used_at IS NULL AND revoked_at IS NULL", [id]);
    return (result.rowCount ?? 0) > 0;
  }

  async list(limit = 200): Promise<Invite[]> {
    const { rows } = await this.pool.query<Row>(`SELECT ${COLUMNS} FROM auth.invite ORDER BY created_at DESC LIMIT $1`, [limit]);
    return rows.map(toInvite);
  }
}
```

```
import { AccountDataError, type AccountDataClient } from "../src/lib/account-data";
import type { EmailMessage } from "../src/lib/email";
import { loadEnv } from "../src/lib/env";
import { migrate } from "../src/lib/migrate";
import { buildServices, type Services } from "../src/lib/services";
import { freshSchema } from "./helpers";

export const BASE = "http://localhost:3100";
export const PASSWORD = "correct horse battery staple";

export type Harness = Awaited<ReturnType<typeof makeHarness>>;

/** The real Better Auth, on a real Postgres, with a mailbox in place of email and a stand-in for the Python API. */
export async function makeHarness(options: { adminEmail?: string | null; accountData?: AccountDataClient; inviteTtlDays?: number; production?: boolean } = {}) {
  const pool: Pool = await freshSchema();
  const base = options.production ? "https://app.example.com" : BASE;
  const sent: EmailMessage[] = [];
  const deletedUsers: string[] = [];
  const accountData: AccountDataClient = options.accountData ?? { delete: async (id) => void deletedUsers.push(id) };
  const env = loadEnv({
    DATABASE_URL: "postgresql://unused@localhost/scraper_web_test",
    BETTER_AUTH_SECRET: "a-test-only-secret-that-is-long-enough-0123456789",
    BETTER_AUTH_URL: base,
    API_URL: "http://api.test",
    API_AUDIENCE: "http://api.test",
    SERVICE_SECRET: "t".repeat(24),
    EMAIL_TRANSPORT: options.production ? "resend" : "log",
    ...(options.production ? { NODE_ENV: "production", RESEND_API_KEY: "re_test", EMAIL_FROM: "Page Chat <no-reply@example.com>" } : {}),
    ADMIN_EMAIL: options.adminEmail === null ? "" : (options.adminEmail ?? "owner@example.com"),
    INVITE_TTL_DAYS: String(options.inviteTtlDays ?? 7),
  });
  const services: Services = buildServices(env, { pool, sendEmail: async (message) => void sent.push(message), accountData });
  await migrate(services.auth, pool);

  const call = (path: string, init: { method?: string; body?: unknown; headers?: Record<string, string>; cookie?: string } = {}) =>
    services.auth.handler(
      new Request(`${base}/api/auth${path}`, {
        method: init.method ?? (init.body === undefined ? "GET" : "POST"),
        headers: { "content-type": "application/json", origin: base, ...(init.cookie ? { cookie: init.cookie } : {}), ...init.headers },
        body: init.body === undefined ? undefined : JSON.stringify(init.body),
      }),
    );

  const cookieFrom = (response: Response) => response.headers.getSetCookie().map((c) => c.split(";")[0]).join("; ");
  const linkIn = (message: EmailMessage) => /https?:\/\/\S+/.exec(message.text)![0];
  const lastEmailTo = (to: string) => [...sent].reverse().find((m) => m.to === to);

  const signUp = (email: string, token?: string, password = PASSWORD) =>
    call("/sign-up/email", { body: { email, password, name: email.split("@")[0] }, headers: token ? { "x-invite-token": token } : {} });
  const signIn = (email: string, password = PASSWORD) => call("/sign-in/email", { body: { email, password } });

  /** Follow the verification link from the latest email to `email`. */
  const verify = async (email: string) => {
    const message = lastEmailTo(email);
    if (!message) throw new Error(`no email was sent to ${email}`);
    return services.auth.handler(new Request(linkIn(message), { headers: { origin: base } }));
  };

  /** Invite, sign up, verify and sign in. Returns the session cookie. */
  const makeUser = async (email: string) => {
    const { token } = await services.invites.create(email, null);
    const response = await signUp(email, token);
    if (response.status !== 200) throw new Error(`sign-up failed: ${response.status} ${await response.text()}`);
    await verify(email);
    const session = await signIn(email);
    if (session.status !== 200) throw new Error(`sign-in failed: ${session.status}`);
    return cookieFrom(session);
  };

  /** The first administrator: ADMIN_EMAIL signs up with no invitation. */
  const makeAdmin = async (email = "owner@example.com") => {
    const response = await signUp(email);
    if (response.status !== 200) throw new Error(`admin sign-up failed: ${response.status} ${await response.text()}`);
    await verify(email);
    return cookieFrom(await signIn(email));
  };

  const userIdOf = async (email: string) => (await pool.query(`SELECT id FROM auth."user" WHERE email = $1`, [email])).rows[0]?.id as string | undefined;

  const unreachableApi = (status: number): AccountDataClient => ({
    delete: async () => {
      throw new AccountDataError(status);
    },
  });

  return { base, pool, services, sent, deletedUsers, call, cookieFrom, linkIn, lastEmailTo, signUp, signIn, verify, makeUser, makeAdmin, userIdOf, unreachableApi };
}
```

```
export function accountDataClient(options: { apiUrl: string; serviceSecret: string; fetchImpl?: typeof fetch; timeoutMs?: number }): AccountDataClient {
  const { apiUrl, serviceSecret, fetchImpl = fetch, timeoutMs = 15_000 } = options;
  return {

          headers: { "content-type": "application/json", "x-service-secret": serviceSecret },

        });
      } catch {

      }
      if (response.status !== 204) throw new AccountDataError(response.status);
    },
  };
```

- [ ] **Step 8: Create `web/src/lib/auth.ts`**

This is the first version of the Better Auth configuration: email and password with mandatory confirmation, password reset, the invitation check, and the first administrator. Later tasks add tokens, account deletion and production hardening to the same file.

The invitation check is a hook on `POST /sign-up/email`; the token travels in the `x-invite-token` header. `ADMIN_EMAIL` is the one address allowed to skip it, and only while nobody is an administrator. A user cannot choose their own role: the sign-up form's `role` is ignored and only the create hook can set it.

```
import { betterAuth } from "better-auth";
import { APIError, createAuthMiddleware } from "better-auth/api";
import { nextCookies } from "better-auth/next-js";
import { admin } from "better-auth/plugins";
import type { Pool } from "pg";
import type { AccountDataClient } from "./account-data";
import { resetMessage, verifyMessage, type EmailSender } from "./email";
import type { WebEnv } from "./env";
import { InviteStore, normalizeEmail } from "./invites";

export const INVITE_HEADER = "x-invite-token";
export const INVITE_REQUIRED_MESSAGE = "Sign-up needs a valid invitation for this email address.";
const DAY = 60 * 60 * 24;

export type AuthDeps = {
  env: WebEnv;
  pool: Pool;
  sendEmail: EmailSender;
  invites: InviteStore;
  accountData: AccountDataClient;
};

export function createAuth({ env, pool, sendEmail, invites, accountData }: AuthDeps) {
  /** The very first account may be made without an invitation: the address in ADMIN_EMAIL, while nobody is an admin yet. */
  async function mayBecomeFirstAdmin(email: string): Promise<boolean> {
    if (!env.adminEmail || normalizeEmail(email) !== env.adminEmail) return false;
    const { rowCount } = await pool.query(`SELECT 1 FROM auth."user" WHERE role = 'admin' LIMIT 1`);
    return rowCount === 0;
  }

  return betterAuth({
    appName: "Page Chat",
    baseURL: env.baseUrl,
    secret: env.authSecret,
    database: pool,
    trustedOrigins: [env.baseUrl, ...env.trustedOrigins],
    emailAndPassword: {
      enabled: true,
      requireEmailVerification: true,
      minPasswordLength: 12,
      resetPasswordTokenExpiresIn: 60 * 60,
      revokeSessionsOnPasswordReset: true,
      sendResetPassword: async ({ user, url }) => sendEmail(resetMessage({ to: user.email, url })),
    },
    emailVerification: {
      sendOnSignUp: true,
      autoSignInAfterVerification: true,
      sendVerificationEmail: async ({ user, url }) => sendEmail(verifyMessage({ to: user.email, url })),
    },
    session: { expiresIn: 7 * DAY, updateAge: DAY },
    hooks: {
      // Invite-only: an account can be created only with the single-use token that was emailed to that exact address.
      before: createAuthMiddleware(async (ctx) => {
        if (ctx.path !== "/sign-up/email") return;
        const email = String((ctx.body as { email?: unknown } | undefined)?.email ?? "");
        if (!email || (await mayBecomeFirstAdmin(email))) return; // an empty address fails the sign-up's own validation
        const result = await invites.check(ctx.headers?.get(INVITE_HEADER) ?? "", email);
        if (!result.ok) throw new APIError("FORBIDDEN", { message: INVITE_REQUIRED_MESSAGE, code: "INVITE_REQUIRED" });
      }),
    },
    databaseHooks: {
      user: {
        create: {
          before: async (user) => ((await mayBecomeFirstAdmin(user.email)) ? { data: { ...user, role: "admin" } } : { data: user }),
          after: async (user) => invites.consume(user.email),
        },
      },
    },
    plugins: [
      admin(),
      nextCookies(), // keep last
    ],
  });
}

export type Auth = ReturnType<typeof createAuth>;
```

```
  pool: Pool;
  invites: InviteStore;
  sendEmail: EmailSender;
  accountData: AccountDataClient;
  auth: Auth;
};

/** Everything the routes use, wired together. Tests pass their own pool, email sender and API client. */
export function buildServices(env: WebEnv, overrides: Partial<Pick<Services, "pool" | "sendEmail" | "accountData">> = {}): Services {
  const pool = overrides.pool ?? makePool(env.databaseUrl);
  const invites = new InviteStore(pool, env.inviteTtlDays);
  const sendEmail = overrides.sendEmail ?? (env.emailTransport === "resend" ? resendSender({ apiKey: env.resendApiKey, from: env.emailFrom }) : logSender());

  return { env, pool, invites, sendEmail, accountData, auth: createAuth({ env, pool, sendEmail, invites, accountData }) };
}

const KEY = Symbol.for("page-chat.services");

/** One set of services per server process (and across hot reloads in development). Built on first use, so `next build` needs no secrets. */
export function getServices(): Services {
  const holder = globalThis as unknown as Record<symbol, Services | undefined>;
  return (holder[KEY] ??= buildServices(loadEnv()));
```

- [ ] **Step 3: Create `web/src/lib/admin-invites.ts`**

Plain functions of a `Request`, so they are tested without a server. Three rules matter: only a signed-in, non-banned administrator may use them; every change must carry an `Origin` that is this app (cookies are sent with cross-site requests, and Next.js route handlers have no CSRF protection of their own); and the invitation token is emailed, never returned to the caller. If the email cannot be sent the invitation is revoked, so nothing is left open that nobody received.

```
import { inviteMessage } from "./email";
import { normalizeEmail, type Invite } from "./invites";
import type { Services } from "./services";

const json = (body: unknown, status = 200) => Response.json(body, { status, headers: { "cache-control": "no-store" } });
const fail = (status: number, code: string, message: string) => json({ error: { code, message } }, status);

const view = (invite: Invite) => ({
  id: invite.id,
  email: invite.email,
  status: invite.status,
  createdAt: invite.createdAt.toISOString(),
  expiresAt: invite.expiresAt.toISOString(),
  usedAt: invite.usedAt?.toISOString() ?? null,
  revokedAt: invite.revokedAt?.toISOString() ?? null,
});

/** The invitation routes, as plain functions of a Request so they can be tested without a server. */
export function adminInviteHandlers(services: Services) {
  const { auth, invites, env, pool, sendEmail } = services;

  async function requireAdmin(request: Request): Promise<{ userId: string } | Response> {
    const session = await auth.api.getSession({ headers: request.headers });
    if (!session) return fail(401, "unauthorized", "Sign in to continue.");
    const user = session.user as { id: string; role?: string | null; banned?: boolean | null };
    if (user.role !== "admin" || user.banned) return fail(403, "forbidden", "Only administrators can do that.");
    return { userId: user.id };
  }

  /** Cookies are sent with cross-site requests too, so a change must come from one of our own pages. */
  function fromOurOwnPage(request: Request): boolean {
    if (request.method === "GET" || request.method === "HEAD") return true;
    const origin = request.headers.get("origin");
    return origin !== null && [env.baseUrl, ...env.trustedOrigins].includes(origin);
  }

  async function guarded(request: Request): Promise<{ userId: string } | Response> {
    if (!fromOurOwnPage(request)) return fail(403, "bad_origin", "This request did not come from this site.");
    return requireAdmin(request);
  }

  return {
    async list(request: Request): Promise<Response> {
      const admin = await guarded(request);
      if (admin instanceof Response) return admin;
      return json({ invites: (await invites.list()).map(view) });
    },

    async create(request: Request): Promise<Response> {
      const admin = await guarded(request);
      if (admin instanceof Response) return admin;
      const body = (await request.json().catch(() => null)) as { email?: unknown } | null;
      const email = typeof body?.email === "string" ? normalizeEmail(body.email) : "";
      if (!email || email.length > 254 || !/^[^@\s]+@[^@\s]+\.[^@\s]+$/.test(email)) return fail(422, "invalid", "Enter a valid email address.");
      const existing = await pool.query(`SELECT 1 FROM auth."user" WHERE lower(email) = $1`, [email]);
      if (existing.rowCount) return fail(409, "already_has_account", "That address already has an account.");
      const { invite, token } = await invites.create(email, admin.userId);
      const url = `${env.baseUrl}/sign-up?invite=${encodeURIComponent(token)}&email=${encodeURIComponent(email)}`;
      try {
        await sendEmail(inviteMessage({ to: email, url, ttlDays: env.inviteTtlDays }));
      } catch {
        await invites.revoke(invite.id); // an invitation nobody received must not stay open
        return fail(502, "email_failed", "The invitation could not be emailed. Nothing was created; try again.");
      }
      return json({ invite: view(invite) }, 201);
    },

    async revoke(request: Request, id: string): Promise<Response> {
      const admin = await guarded(request);
      if (admin instanceof Response) return admin;
      return (await invites.revoke(id)) ? new Response(null, { status: 204 }) : fail(404, "not_found", "There is no waiting invitation with that id.");
    },
  };
}
```

- [ ] **Step 1: Create `web/scripts/e2e.ts`**

```
/**
 * Drives a running web app and a running Python API through a person's whole life cycle:
 * sign up as the first administrator, invite someone, check that the API accepts the web app's tokens (and nothing else),
 * keep two people's data apart, and delete an account. Start both servers with scripts/e2e.sh, which calls this.
 */
import assert from "node:assert/strict";
import { readFileSync } from "node:fs";
import { Pool } from "pg";

const WEB = process.env.WEB_URL!;
const API = process.env.API_URL!;
const LOG = process.env.WEB_LOG!;
const DATABASE_URL = process.env.DATABASE_URL!;
const ADMIN = (process.env.ADMIN_EMAIL ?? "owner@example.com").toLowerCase();
const PASSWORD = "correct horse battery staple";
const origin = { origin: WEB };

const step = (text: string) => console.log(`\n== ${text}`);
const ok = (text: string) => console.log(`   ok  ${text}`);

async function emailLink(to: string, subject: string): Promise<string> {
  for (let i = 0; i < 50; i++) {
    const log = readFileSync(LOG, "utf8");
    const at = log.lastIndexOf(`[email to ${to}] ${subject}`);
    const link = at >= 0 ? /https?:\/\/\S+/.exec(log.slice(at))?.[0] : undefined;
    if (link) return link;
    await new Promise((resolve) => setTimeout(resolve, 100));
  }
  throw new Error(`no "${subject}" email for ${to} appeared in the web server's log`);
}

const cookieOf = (response: Response) => response.headers.getSetCookie().map((c) => c.split(";")[0]).join("; ");
const web = (path: string, init: RequestInit & { cookie?: string } = {}) =>
  fetch(`${WEB}${path}`, { ...init, redirect: "manual", headers: { "content-type": "application/json", ...origin, ...(init.cookie ? { cookie: init.cookie } : {}), ...(init.headers as Record<string, string>) } });
const api = (path: string, token?: string, init: RequestInit = {}) =>
  fetch(`${API}${path}`, { ...init, headers: { "content-type": "application/json", ...(token ? { authorization: `Bearer ${token}` } : {}), ...(init.headers as Record<string, string>) } });

async function join(email: string, inviteToken?: string): Promise<{ cookie: string; token: string; id: string }> {
  const signUp = await web("/api/auth/sign-up/email", { method: "POST", body: JSON.stringify({ email, password: PASSWORD, name: email.split("@")[0] }), headers: inviteToken ? { "x-invite-token": inviteToken } : {} });
  const signUpText = await signUp.text();
  assert.equal(signUp.status, 200, `sign-up for ${email}: ${signUpText}`);
  assert.equal((await web("/api/auth/sign-in/email", { method: "POST", body: JSON.stringify({ email, password: PASSWORD }) })).status, 403, "sign-in must wait for the confirmed address");
  const verified = await fetch(await emailLink(email, "Confirm your email address"), { redirect: "manual", headers: origin });
  assert.ok([200, 302].includes(verified.status), `verification link answered ${verified.status}`);
  const signedIn = await web("/api/auth/sign-in/email", { method: "POST", body: JSON.stringify({ email, password: PASSWORD }) });
  assert.equal(signedIn.status, 200);
  const cookie = cookieOf(signedIn);
  const token = ((await (await web("/api/auth/token", { cookie })).json()) as { token: string }).token;
  const session = (await (await web("/api/auth/get-session", { cookie })).json()) as { user: { id: string } };
  return { cookie, token, id: session.user.id };
}

async function main() {
  const pool = new Pool({ connectionString: DATABASE_URL });
  const rows = async (table: string, id: string) => Number((await pool.query(`SELECT count(*) FROM app.${table} WHERE user_id = $1`, [id])).rows[0].count);

  step("the API refuses anyone without a token");
  assert.equal((await api("/health")).status, 200);
  assert.equal((await api("/state")).status, 401);
  assert.equal((await api("/state", "garbage.token.here")).status, 401);
  ok("no token and a garbage token are both refused; /health is open");

  step("the first administrator signs up with no invitation");
  const owner = await join(ADMIN);
  ok(`signed up, confirmed by email and signed in as ${owner.id}`);

  step("the API accepts the web app's token, and only an untampered one");
  const state = await api("/state", owner.token);
  const stateText = await state.text();
  assert.equal(state.status, 200, stateText);
  assert.equal((JSON.parse(stateText) as { user: { id: string } }).user.id, owner.id);
  const [head, body, signature] = owner.token.split(".");
  const flipped = signature.startsWith("A") ? `B${signature.slice(1)}` : `A${signature.slice(1)}`;
  assert.equal((await api("/state", `${head}.${body}.${flipped}`)).status, 401);
  assert.equal((await api("/state", `${head}.${Buffer.from(JSON.stringify({ sub: "someone-else", aud: "x", iss: "y", exp: 9999999999 })).toString("base64url")}.${signature}`)).status, 401);
  ok("the API knows the user from the token alone; a changed signature or a rewritten payload is refused");

  step("invite someone");
  assert.equal((await web("/api/admin/invites", { method: "POST", cookie: owner.cookie, body: JSON.stringify({ email: "bob@example.com" }), headers: { origin: "https://evil.example" } })).status, 403);
  const created = await web("/api/admin/invites", { method: "POST", cookie: owner.cookie, body: JSON.stringify({ email: "bob@example.com" }) });
  assert.equal(created.status, 201);
  const link = new URL(await emailLink("bob@example.com", "You are invited to Page Chat"));
  assert.equal(link.pathname, "/sign-up");
  const inviteToken = link.searchParams.get("invite")!;
  assert.equal((await web("/api/auth/sign-up/email", { method: "POST", body: JSON.stringify({ email: "mallory@example.com", password: PASSWORD, name: "m" }), headers: { "x-invite-token": inviteToken } })).status, 403);
  const bob = await join("bob@example.com", inviteToken);
  ok(`bob joined with the emailed link as ${bob.id}; the same link cannot make someone else's account`);

  step("two people's data stay apart");
  assert.equal((await api("/settings/url", owner.token, { method: "PUT", body: JSON.stringify({ value: "https://owner.example/" }) })).status, 204);
  assert.equal((await api("/settings/url", bob.token, { method: "PUT", body: JSON.stringify({ value: "https://bob.example/" }) })).status, 204);
  const ownerState = (await (await api("/state", owner.token)).json()) as { settings: { url: string }; user: { id: string } };
  const bobState = (await (await api("/state", bob.token)).json()) as { settings: { url: string }; user: { id: string } };
  assert.equal(ownerState.settings.url, "https://owner.example/");
  assert.equal(bobState.settings.url, "https://bob.example/");
  assert.notEqual(ownerState.user.id, bobState.user.id);
  assert.ok((await rows("prefs", bob.id)) > 0);
  ok("each person sees only their own saved settings");

  step("deleting an account removes the person's data in the API first");
  const deletion = await web("/api/auth/delete-user", { method: "POST", cookie: bob.cookie, body: JSON.stringify({ password: PASSWORD }) });
  const deletionText = await deletion.text();
  assert.equal(deletion.status, 200, deletionText);
  assert.equal(await rows("prefs", bob.id), 0);
  assert.equal((await pool.query(`SELECT 1 FROM auth."user" WHERE id = $1`, [bob.id])).rowCount, 0);
  assert.ok((await rows("prefs", owner.id)) > 0, "the owner's data must be untouched");
  ok("bob's account and everything the API held for him are gone; the owner's data is intact");

  await pool.end();
  console.log("\nALL CHECKS PASSED");
}

main().catch((error) => {
  console.error("\nFAILED:", error instanceof Error ? error.message : error);
  process.exit(1);
});
```

- [ ] **Step 2: Create `web/scripts/e2e.sh`**

The script refuses to start if either port is already in use (a leftover server would be tested by mistake), refuses a database whose name lacks "test", and stops the real server processes when it ends. It runs the Next.js development server, not `next start`, because a production server insists on https and a real email service, which is right for a deployment and wrong for a check over plain http on this machine.

```bash
#!/usr/bin/env bash
# Start the web app and the Python API on one scratch database and run scripts/e2e.ts against them.
#
#   E2E_DATABASE_URL=postgresql://user@host/scraper_e2e_test npm run e2e
#
# The database must be a scratch one: the script drops its `auth` and `app` schemas first.
set -euo pipefail
cd "$(dirname "$0")/.."
: "${E2E_DATABASE_URL:?set E2E_DATABASE_URL to a scratch database (its auth and app schemas are dropped)}"
case "$E2E_DATABASE_URL" in *test*) ;; *) echo "refusing: the database name must contain 'test'" >&2; exit 2;; esac

WEB_PORT=${WEB_PORT:-3100}; API_PORT=${API_PORT:-8180}
WEB_URL="http://localhost:$WEB_PORT"; API_URL="http://localhost:$API_PORT"
for port in "$WEB_PORT" "$API_PORT"; do  # a leftover server on these ports would be tested by mistake
  if lsof -ti "tcp:$port" -sTCP:LISTEN > /dev/null 2>&1; then echo "port $port is already in use; stop that server or set WEB_PORT / API_PORT" >&2; exit 2; fi
done
SECRET=$(node -e "console.log(require('crypto').randomBytes(24).toString('base64url'))")
LOGS=$(mktemp -d)
stop_servers() {
  # `uv run` and `npx` start the real server as a child; stop the children too
  for pid in $(jobs -p); do pkill -TERM -P "$pid" 2>/dev/null || true; kill "$pid" 2>/dev/null || true; done
  sleep 0.5; rm -rf "$LOGS"
}
trap stop_servers EXIT

psql "$E2E_DATABASE_URL" -q -c "DROP SCHEMA IF EXISTS auth CASCADE" -c "DROP SCHEMA IF EXISTS app CASCADE" -c "CREATE SCHEMA auth"
export DATABASE_URL="$E2E_DATABASE_URL" BETTER_AUTH_SECRET="$(node -e "console.log(require('crypto').randomBytes(32).toString('base64url'))")" \
  BETTER_AUTH_URL="$WEB_URL" API_URL="$API_URL" API_AUDIENCE="$API_URL" SERVICE_SECRET="$SECRET" \
  EMAIL_TRANSPORT=log ADMIN_EMAIL=owner@example.com

npm run --silent migrate
# The development server, not `next start`: a production server insists on https and a real email service, which is right
# for a deployment and wrong for a check over plain http on this machine.
npx next dev -p "$WEB_PORT" > "$LOGS/web.log" 2>&1 &
(cd .. && SCRAPER_HOSTED=true SCRAPER_DATABASE_URL="$E2E_DATABASE_URL" SCRAPER_JWKS_URL="$WEB_URL/api/auth/jwks" SCRAPER_JWT_ISSUER="$WEB_URL" \
  SCRAPER_JWT_AUDIENCE="$API_URL" SCRAPER_SERVICE_SECRET="$SECRET" SCRAPER_API_KEY=not-a-real-key SCRAPER_CORS_ORIGINS="$WEB_URL" \
  SCRAPER_HOST=127.0.0.1 SCRAPER_PORT="$API_PORT" exec uv run python -m scraper_api > "$LOGS/api.log" 2>&1) &

for url in "$WEB_URL/" "$API_URL/health"; do
  for _ in $(seq 1 100); do curl -fs "$url" > /dev/null 2>&1 && break; sleep 0.2; done
  curl -fs "$url" > /dev/null 2>&1 || { echo "did not start: $url"; tail -20 "$LOGS"/*.log; exit 1; }
done
WEB_URL="$WEB_URL" API_URL="$API_URL" WEB_LOG="$LOGS/web.log" npx tsx scripts/e2e.ts || { echo "--- web log"; tail -15 "$LOGS/web.log"; echo "--- api log"; tail -15 "$LOGS/api.log"; exit 1; }
```

````markdown
## How it fits together

- `src/lib/auth.ts` is the whole Better Auth configuration, in one place.
- An account can only be created with the single-use token emailed to that exact address (`x-invite-token` header on `POST /api/auth/sign-up/email`). The first administrator is the one address in `ADMIN_EMAIL`.

- Deleting an account first asks the Python API to erase that person's data; if it cannot, the account stays and the deletion can be retried.
````

````markdown
## 6. The web app

The web app (`web/`, Next.js) is deployed separately, usually on Vercel with the project's root directory set to `web`. It uses the same database, in the `auth` schema, through the `scraper_web` role from section 1.

Create its tables once, and again after upgrading Better Auth (it is safe to repeat):

```bash
cd web && DATABASE_URL=... BETTER_AUTH_SECRET=... BETTER_AUTH_URL=... API_URL=... SERVICE_SECRET=... EMAIL_TRANSPORT=resend RESEND_API_KEY=... EMAIL_FROM=... npm run migrate
```

Email goes through Resend: verify the sending domain there, create an API key, and set `RESEND_API_KEY` and `EMAIL_FROM` (such as `Page Chat <no-reply@your-domain>`). The app refuses to start in production with the `log` email transport, because that prints invitation links to the server log.

Settings that must agree between the web app and the API (the most common mistake is a trailing slash or a different scheme):

| Web app | Python API | Notes |
|---|---|---|
| `BETTER_AUTH_URL` | `SCRAPER_JWT_ISSUER` | Exactly equal, no trailing slash. Also the base of `SCRAPER_JWKS_URL`, which is `<BETTER_AUTH_URL>/api/auth/jwks` |

The first administrator: set `ADMIN_EMAIL` and sign up with that address. It needs no invitation and becomes the administrator; after that, everyone needs an invitation (sent from the administrator's invitation routes), and `ADMIN_EMAIL` stops having any effect.

### Known limitations

- **A token outlives the account for up to 15 minutes.** After someone is banned or deleted, a token they already hold still passes the API's check until it expires. A ban ends their sessions at once so they cannot get a new token, and deletion erases the API's data first, but a token in hand could create an empty session row again in that window. It holds no data.
- **Response timing can show whether an address has an account.** Password reset sends its email before answering, so a request for a real address takes longer than one for an unknown address. The responses are identical; the timing is not hidden.
- **An invitation link is a credential.** Anyone who holds the link can set the password for that address (and the confirmation email then goes to the real owner). Treat it like a password reset link.
````
